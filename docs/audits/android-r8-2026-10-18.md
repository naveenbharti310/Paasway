# Android R8 release optimization repair

Google Play's warning refers to published0.3.10(16), with2 percent DEX obfuscation and a February2027 deadline. Public testing17 still used the same Android optimization defaults.

## Confirmed cause

The pinned Expo57 template defaults `android.enableMinifyInReleaseBuilds` and `android.enableShrinkResourcesInReleaseBuilds` to false. The app's build-properties configuration previously configured only iOS static frameworks. The generated release also selected the legacy `proguard-android.txt` default rather than Android's optimizing default.

## Repair in candidate0.3.12(18)

Explicitly enable release R8 minification and resource shrinking through supported Expo build-properties settings. A fail-closed config plugin selects `proguard-android-optimize.txt` and requests native SYMBOL_TABLE data. Dependency-owned reflection/JNI/React Native/Firebase consumer rules remain intact. No app-wide keep-all, dontobfuscate, dontoptimize, dontshrink or global dontwarn escape hatch was added.

Generated native configuration is checked, not just the TypeScript source. A separate bundle verifier requires an embedded mapping produced by R8, real class renaming and base DEX. It preserves the exact mapping and records its hash alongside the bundle hash for crash deobfuscation. Native symbol metadata availability is reported rather than invented. Play receives the mapping embedded in the bundle; CI evidence must also preserve it.

## Validation and limitations

The generated Android project was inspected locally using an explicit demo Firebase configuration, not production credentials. It enables both flags, consumes them in the release build type, selects optimizing rules and requests symbol tables. Mobile regression and artifact-verifier failure tests accompany the change. Required CI, actual signed minified compilation and fresh minified native flow testing remain separate gates.

A successful flag change or mapping rename fraction is NOT Google's DEX percentage. Do not mark the Play warning resolved until Google processes the optimized candidate and the Console measurement is checked. The old warning can continue to reference16 while that older production artifact remains served. Do not silently replace production16 or beta17 before candidate18 validation. Actual Play-installed authenticated/device behavior is not certified by an offline ADB installation, which previously hit licensing and outdated Play services restrictions.

This repair does not claim to resolve the separate Android15 dependency edge-to-edge deprecations or Android16 adaptive layout work tracked in issue29.
